# 0002 · 以限额的临时备份支持续传

**状态：**已采纳。

**背景：**大体积账户在低带宽链路下载耗时，断线后重新下载的成本高。直接流式压缩不需要暂存整包，但生成中的压缩流不能保证断点后的字节一致；前端缓存完整 ZIP 则会显著增加网页内存占用。

**决定：**后台在私有持久卷生成限额 ZIP，完成后才发布。浏览器以原生下载读取固定字节内容，重启后就绪包可在时限内凭原权限续传。按任务、账户和全局限制空间、并发和网速，每次下载重新鉴权。保留既有直流接口供旧调用方使用，但不提供续传。

**影响：**部署需留出打包空间；包是临时副本，到期或账户清除时必须停止下载并清理。备份没有跨文件的事务快照保证。反向代理不得缓存、缓冲或再次压缩下载响应，应保留 Range、If-Range 与 ETag；默认限额及速率可按实际容量调整。
